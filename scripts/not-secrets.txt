# Variables that live in a secret-bearing file and are NOT credentials.
#
# C-9 asks one question with no blind spot: is every variable in every
# secret-bearing file either named in docs/king-rotation.md or listed here?
# Neither means nobody has looked at it, and the audit goes red.
#
# It did not always ask that. Until 2026-09-11 it selected "secret-shaped"
# variables with the pattern KEY|TOKEN|SECRET|PASSWORD|DSN|URL and then
# reported how many of THOSE were documented. LANGFUSE_OTLP_AUTH (the Langfuse
# key pair), NTFY_ALERT_TOPIC (the unguessable half of an unauthenticated ntfy
# topic) and MACHINE_ID_SALT matched none of those words, so they were absent
# from the set being checked and from the total being reported, and C-9 passed
# on a rotation list missing three credentials. A check whose denominator comes
# from the same heuristic as its test cannot fail on what the heuristic misses.
#
# A value-shape heuristic was tried instead and has a different hole, not a
# smaller one: LANGFUSE_OTLP_AUTH contains a space (it is a `Basic …` header)
# and MACHINE_ID_SALT is 19 characters. So the heuristic was dropped entirely
# in favour of enumeration, which is why this file exists and is long.
#
# Adding a name here is a claim that a holder of its value gains nothing.
# Make that claim deliberately; it is the only thing standing between a new
# credential and silence.
#
# Format: one variable name per line. Blank lines and #-comments ignored.
# Reviewed 2026-09-11 against the running deployment.
